# PoW | Pain of Word

將混亂的 Word 格式整理成可理解、可檢查、可維護的文件。

協作文件常混有不同來源的字型、直接格式、Tab 與空白縮排。PoW 的目標是依據使用者確認的格式規格，辨識問題、修正支援的格式並保留原文內容。

## 狀態

第一版可在 localhost 操作。提供 DOCX 檢查、段落角色確認、規格設定、局部修正匯出及 AI 輔助分類。這是有明確支援範圍的本機工具，並非任意 Word 文件的全自動修復器。

## 啟動

需要 Python 3.11 或以上版本，以及 Chrome、Edge 或其他現代瀏覽器。

Windows 雙擊 `start.cmd`。首次會建立 `.venv` 並安裝必要套件，接著開啟 <http://127.0.0.1:8765>。終端機按 Ctrl+C 停止服務。

手動啟動：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pow_app
```

macOS／Linux 可使用 `.venv/bin/python` 執行相同 Python 模組。Windows 啟動器以 Windows 實測；其他平台尚未測試。

無資料庫、無前端建置程序、無外部字型或 CDN。第一次安裝套件需要網路；使用已安裝的本機模型時不需雲端 API。

## 第一版流程

1. 建立或載入格式規格，確認字型、字級、縮排、行距與頁邊界。
2. 選取 DOCX，透過格式解析及 AI 輔助查看段落、格式差異與需人工確認的角色。
3. 預覽修改項目，下載修正版 DOCX 與檢查報告。

第一版採原生網站介面與 FastAPI 本機服務，先以可編輯規格處理文件，暫不自動從範本擷取規格。DOCX 解析與修正在本機後端執行，未上傳至 PoW 遠端伺服器。

## 使用方式

1. 調整字型、字級、首行縮排、行距、段落間距與 A4 頁邊界；規格可匯入／匯出 JSON。
2. 選取 `.docx`，確認每段角色、目前格式與修改預覽。規則提供初步角色，可手動修正。
3. 如需 AI，展開模型設定、連接服務、選擇模型，確認資料範圍後分析。
4. 確認後下載 ZIP，內含 `corrected.docx` 與 `report.json`。原始檔不覆寫。
5. 以左側原檔、右側轉換後的瀏覽器版面預覽核對，再在 Word 開啟輸出確認分頁。瀏覽器預覽不等同 Word 排版引擎，也不更新目錄欄位。

## AI 接入規劃

- 雲端：選擇 OpenAI API，在模型設定輸入 key，或先於啟動終端設定 `OPENAI_API_KEY`。使用 Responses API；請選擇支援結構化輸出的模型。API 請求會送出已預覽的段落與規格，並可能產生費用。
- 本機 Ollama：先安裝並自行下載模型、啟動服務，再連接 `http://127.0.0.1:11434`。實測 `qwen3:1.7b` 可回傳通過驗證的分類。分類品質仍需人工確認。
- 本機 OpenAI 相容服務：使用含 `/v1` 的端點，例如 `http://127.0.0.1:1234/v1`。已實作模型列舉與 Chat Completions JSON 呼叫；尚未對所有相容服務實測。
- AI 提供段落角色、歧義與理由；程式驗證建議後，再依使用者確認的規格執行修正。
- API key 不放進前端、Git 或報告；模型分析前顯示將送出的資料範圍。
- AI 不可用時，可手動確認角色並繼續規則式修正；不將本機模型失敗自動轉送雲端。

API key 保存在本機服務記憶體，不寫入瀏覽器儲存區或設定檔，停止服務後清除。請勿把金鑰放入原始碼或提交 Git。OpenAI 真實付費請求尚未實測；Ollama 已完成真實連線測試。接入架構見 [AI 整合設計](docs/ai-integration.md)。

## 支援範圍

- 目前處理單節、橫式主文件的一般段落，支援正文與前四級標題。標題保留原本的編號文字，設定大綱層級，不新增多層自動編號。
- 含自動編號、圖片、公式、欄位、超連結、註腳參照等複雜物件的段落只顯示、不修改。表格及頁首頁尾維持原樣。
- 追蹤修訂、多節或啟用編輯保護的文件只檢查、不匯出。巨集、數位簽章、加密、損毀檔案會拒絕。
- 正文粗體及斜體等行內強調保留。段首空白與 Tab 只有勾選清理後才會移除，段落內部空白不清理。
- 啟動時依可用記憶體設定上傳上限32–256 MB，解壓容量上限128–1024 MB；這是保護上限，不保證所有接近上限的文件均能順暢處理。單一XML上限24 MB、封裝項目2000個、主文件段落2000個。AI分析資料上限24,000字元，較長文件可手動處理。
- 瀏覽器版面預覽最多64 MB（低記憶體時更低）；超過時略過預覽，仍可在文件處理限制內修正與匯出。預覽採sandbox隔離、封鎖外部資源及HTML嵌入內容。
- 文件最多保留8份，快取容量依可用記憶體設定128–1024 MB，30分鐘未使用會清除；也可手動清除。服務是單一使用者的本機工作階段，不提供多使用者隔離或公開代管。

## 預覽依賴

`static/vendor`附帶docx-preview 0.4.1（Apache-2.0）及JSZip 3.10.1（MIT授權選項）的發行檔與授權文字，不需要CDN或執行npm建置。兩個JavaScript檔合計約173 KB。保留第三方原始授權；以docx-preview將DOCX轉為HTML呈現，其分頁及欄位支援有限。

## 處理原則

- 保留原檔，輸出新的文件。
- 將確定的格式規則與不確定的語意判斷分開。
- 不全面刪除空白、Tab、粗體或直接格式。
- 保留未修改的 DOCX 封裝部分；不能證明安全保留的結構必須提示或拒絕處理。
- 不將格式檢查通過宣稱為 Word 實際排版完全一致。
- 不將使用者文件或本機資料提交至原始碼倉庫。
