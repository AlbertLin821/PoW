# PoW 產品範圍草案

第一版本機網站已實作可編輯規格、DOCX檢查與修正、角色確認、API與本機模型轉接。實際完成及限制以README與驗證紀錄為準，後續功能仍為規劃。

## 使用者與問題

使用者是共同編寫 Word 報告、企劃書或正式文件的人員。來源不同的文字經常帶入不一致的字型、行距、縮排與直接格式，使編輯者難以找出排版異常原因。

## 三個核心功能

| 功能 | 輸入 | 輸出 |
|---|---|---|
| 格式規格 | 可編輯的字型、標題、縮排、行距與頁面設定 | 使用者確認的規格 JSON |
| 檢查與角色確認 | DOCX、格式規格及選定模型 | 有效格式、AI 建議角色、判斷理由、異常與待確認項目 |
| 安全修正與匯出 | 已確認的段落及修正項目 | 新 DOCX、修改摘要、保留驗證結果 |

## 第一版邊界

- 採原生網站介面，DOCX在FastAPI本機服務處理；AI接入支援雲端API key及本機模型，不要求PoW帳號。
- API key 由後端環境或本機服務保管，不嵌入公開網頁。模型設定包括供應來源、端點、模型與連線狀態；模型名稱不預設為所有端點都可用。
- 本機模型先以 Ollama 為驗證目標。其他 OpenAI 相容服務須逐項驗證模型列舉、結構化輸出及錯誤處理，不能因端點形狀相似就宣稱全面支援。
- 使用者可選擇不呼叫模型，以手動角色確認繼續規則式修正；雲端與本機模型共用同一份規格、建議結構與驗證流程。
- 規則由可編輯表單與 JSON 管理。可先提供通用預設，但不可聲稱適用於所有組織。
- 支援單節一般文字文件，輸出採A4直向單欄：正文、前四級標題、中英文字型、字級、標題粗體、對齊、首行縮排、行距、段落間距與頁邊界；正文行內強調保留。
- 自動辨識只提供候選角色；使用者可以更正。檢查樣式繼承與直接格式，缺少直接設定不等於沒有有效值。
- 原檔只讀，不重新建立整份文件；對選定的 OOXML 屬性做局部修改。
- 先偵測修訂、公式、欄位、內容控制項、浮動物件等複雜結構，再決定保留、略過或拒絕修正，並清楚顯示處理範圍。
- 表格、圖片、註腳、頁首頁尾及引用欄位不可默默刪除。未支援的物件不等於可安全修改其所在區域。
- 限制檔案大小、ZIP 解壓後容量與項目數；拒絕損毀、加密、偽裝副檔名或不支援的格式。
- 連續處理文件時，清除前次角色選擇、檢查結果與下載內容，避免混用。

## 後續功能

1. 從 A 文件擷取規格候選，顯示來源段落與推論依據，由使用者確認後才處理 B。
2. 從規範 PDF 擷取條文與來源頁，對歧義及衝突進行確認。
3. 以同一套規格與處理引擎提供 Codex skill 或 CLI。
4. 加入 Word 或相容引擎的實際渲染與頁面比較。

第一版不承諾任意 PDF 自動理解、任意 DOCX 無損修復、瀏覽器預覽與 Word 分頁完全一致，或由公開網頁直接使用登入中的 Codex 訂閱。

## 形式比較

| 形式 | 優點 | 成本或限制 |
|---|---|---|
| 瀏覽器網站 | 點連結可用、可在本機處理、不需登入 | 有效格式解析需自行實作；不具備 Word 排版引擎 |
| 本機網站加後端 | 可整合 Python 及較完整的驗證工具 | 使用者需要安裝，或另行維護服務與資料保留機制 |
| Codex skill | 可引導規範解讀與複雜例外處理 | 使用者需有對應環境；skill 本身不是文件引擎 |

網站已確定為第一個使用入口。模型呼叫設獨立服務邊界：本機模式由使用者電腦上的後端連到本機模型；公開代管模式由代管後端連到雲端 API，不假設遠端伺服器可以存取使用者的 localhost。規格與處理引擎保持可重用。

## 驗收條件

- 下載 DOCX 可由 Word 開啟，沒有修復提示。
- 未授權改寫的文字逐段一致；允許變更的縮排字元或標記另列紀錄。
- 至少人工核對三個格式判斷，包括中英文字型、首行縮排與頁邊界。
- 修改清單與實際輸出的 XML 一致，不用畫面上的數值代替輸出驗證。
- 以 Word 更新後檢查標題、圖表與欄位是否保留；未做渲染時明確標示。
- 至少測試正常文件、空白輸入、錯誤格式、極端大小及連續操作，記錄預期、實際與結果。
- 未實作或未執行的項目，不標示通過。
- AI 回傳的段落 ID、角色、理由與資料結構須驗證，拒絕未知或重複 ID、額外修改指令及畸形回應；AI 結果不直接寫入 DOCX。
- 連線失敗、金鑰無效、額度不足、模型不存在、逾時與取消皆須保持原檔不變，並可繼續手動操作。
- 切換模型或文件後，遲到的回應不可套用到新的分析工作。
