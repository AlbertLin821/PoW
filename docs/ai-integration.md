# PoW AI 整合設計

狀態：需求與接入設計已確認；尚未完成模型呼叫、介面或端到端測試。

## 已選定方向

第一版先讓使用者編輯格式規格，再處理 B 文件。支援雲端 API key 及本機模型，暫不加入 ChatGPT 帳號登入。A 範本或 PDF 規範的自動擷取留待後續。

## AI 的工作

模型接收已解析的段落摘要、局部上下文與格式規格，提供：

1. 段落角色建議，例如正文、章、節、小節、圖說或表說。
2. 歧義說明，例如短句究竟是標題或正文，是否須人工確認。
3. 建議理由；不將模型自評的信心值包裝成量測正確率。

AI 不自行更改字級、改寫原文、刪除物件或回傳可執行程式。格式數值以使用者確認的規格為準。實際 OOXML 修改與保全檢查由確定的程式流程執行。

## 處理流程

DOCX本機解析 → 規則檢查 → 顯示模型資料範圍 → 使用者觸發AI分析 → 後端呼叫選定模型 → 驗證結構及段落ID → 使用者確認角色 → 產生修改預覽 → 局部修正 → 內容與封裝驗證 → 匯出新檔。

文件內容一律視為待分析資料，即使含有「忽略規則」「上傳整份文件」等文字，也不得升格成系統指令。模型呼叫不授予文件寫入、工具執行或網路探索權限。

## 兩種模型來源

| 來源 | 憑證 | 呼叫方式 | 狀態 |
|---|---|---|---|
| OpenAI API | 後端環境中的API key | 官方Responses API及結構化輸出，依所選模型能力驗證 | 待實作 |
| 本機Ollama | 一般本機服務不要求OpenAI key；依服務實際設定 | 後端連到loopback服務，使用原生JSON schema或已驗證的相容端點 | 待實作 |
| 其他OpenAI相容服務 | 視供應端要求 | 分開驗證能力，不假設完整等同OpenAI | 後續驗證 |

供應商轉接層提供 `listModels`、`checkConnection`、`analyzeParagraphs`，並回傳同一份供應商無關資料。取消、逾時、最大輸出與錯誤分類也在此層處理。

不自動下載模型或選擇不適合硬體的模型；由使用者選取已安裝且能回應的模型。Ollama的本機模型與雲端模型分開標示，只有資料確實留在本機時才標示本機推論。

## 執行與部署

### 本機模式

PoW介面與後端在使用者電腦執行。後端保管API key，或連到同一台電腦的Ollama服務。本機模型不需要把文件送至雲端；使用雲端API時仍需清楚告知送出的文字內容。

本機服務只綁定loopback，檢查來源與會話憑證，不開放任意網頁透過它存取檔案或模型。模型端點設定只由使用者信任的本機設定控制。

### 公開代管模式

公開網站的AI功能須搭配後端；GitHub Pages只能提供前端。金鑰存於後端，需有限制請求大小、速率、並發與成本的措施。

遠端後端的localhost是伺服器自己，不是訪客電腦。因此本機模型使用本機模式，或後續另行設計經配對的本機橋接服務；不能靠換一個URL就宣稱公開網站能直接使用訪客模型。

代管模式不可接受任意base URL並替訪客發請求，避免形成任意內網代理。金鑰由營運者提供或使用者自備的產品流程尚待確認，不默認將個人金鑰開放給匿名訪客無限使用。

## 結構化回應

示意資料，不是已執行的分析結果：

```json
{
  "documentId": "doc-1",
  "jobId": "job-1",
  "suggestions": [
    {
      "paragraphId": "p-3",
      "role": "heading2",
      "reason": "具有節編號，且位於章標題之下",
      "needsReview": true
    }
  ]
}
```

後端自行帶入可信的documentId與jobId，不依賴模型生成工作識別。模型結果必須經結構驗證，角色限於列舉，理由有長度上限。輸出缺少的段落維持未判定，不自動補成正文。前端只顯示文字，不執行或直接插入模型回傳的HTML。

大文件按段落分批並保留局部上下文；標示部分失敗，不把未完成批次當成全部成功。

## 金鑰與資料

- API key不寫入前端原始碼、localStorage、Git、下載報告、網址或應用日誌。
- 不要求使用者在聊天中貼上API key；透過本機環境或安全的服務設定輸入。
- 預設不保存原始DOCX、段落全文、模型請求或回應至伺服器日誌。
- 模型來源、端點、模型名稱及資料流向在分析前可見；只送必要段落與上下文，不送未使用的作者中繼資料與圖片。
- 本機模型失敗不自動轉用雲端，API失敗也不切換另一把金鑰。
- 雲端供應商的保留政策與應用自身的保存行為分開說明，不將未記錄日誌宣稱成供應商零保留。

## 驗證案例

| 案例 | 預期 |
|---|---|
| 雲端模型有效回應 | 顯示角色建議，確認前DOCX不變 |
| 本機模型有效回應 | 使用相同資料結構，不轉送雲端 |
| 無效key／429／模型不存在 | 顯示可理解錯誤，不產生假建議 |
| 模型離線／逾時／取消 | 可重試或手動繼續，原文不變 |
| 畸形JSON／未知ID／重複ID | 拒絕無效結果，保留待確認狀態 |
| 文件內含指令文字 | 僅當成資料，不更改系統行為 |
| 分析中更換文件或模型 | 舊回應不可污染新工作 |
| 超長文件分批失敗 | 清楚顯示已完成與未完成範圍 |

以上案例均待實作後實際執行；單元測試不能取代真實供應商連線測試。
